BountyFit — App Map

Compact guide to the finished proof of concept and the path a bounty listing takes through the code.

Core journey

  1. index.html provides the textarea, sample buttons, verdict area, evidence, score breakdown, and checklist.
  2. app.js reads the listing and calls analyzeListing().
  3. src/analyzer.js extracts signals, applies score adjustments, chooses GO/REVIEW/SKIP, and creates next actions.
  4. app.js renders the result back into the page.

Files worth knowing

  • src/analyzer.js — product kernel: evidence extraction and explainable scoring.
  • tests/analyzer.test.js — regression cases for GO, REVIEW, SKIP, negated interview language, and vague listings.
  • app.js — UI controller and rendering.
  • styles.css — responsive operator-dashboard presentation.
  • server.js — dependency-free local HTTP server for demo recording.

Practice to reuse

When an agent makes a decision for a user, make the decision traceable. Keep the extraction, scoring, and rendering separate; add a regression test for each important policy edge case. In this project, the key example is treating “no interview required” differently from a mandatory interview.
