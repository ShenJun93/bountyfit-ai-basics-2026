# BountyFit — Demo V2

Target: **70–85 seconds**. Judges are not required to test the project, so the video must make the product distinction obvious by itself.

## 0:00–0:08 — Problem

Show the empty app and the evidence-first hero.

Narration:
> "Solo builders can waste hours on opportunities that look good until a missing deadline, hidden hire gate, or mandatory interview appears."

## 0:08–0:27 — GO with complete evidence

Click **GO · complete evidence**.

Show:
- GO verdict;
- verified signal count;
- reward/deadline evidence;
- score breakdown;
- next-action checklist.

Narration:
> "BountyFit only scores what the listing actually proves. This one has cash, a deadline, a code submission path, and explicitly no interview, so it is a GO."

## 0:27–0:48 — REVIEW because facts are missing

Click **REVIEW · facts missing**.

Pause on:
- unresolved fact count;
- deadline unknown;
- submission path unknown;
- REVIEW verdict.

Narration:
> "The important part is what happens when evidence is missing. BountyFit does not invent a deadline or submission route. Missing facts stay unknown, so the result stays REVIEW."

## 0:48–1:05 — SKIP on live gate

Click **SKIP · live gate**.

Show:
- extracted live-interview evidence;
- negative score adjustment;
- SKIP verdict.

Narration:
> "A mandatory live interview violates this builder profile, so the app surfaces the blocker immediately instead of optimizing only for prize size."

## 1:05–1:18 — Close

Show the four sample chips, local-first note, and result panel.

Narration:
> "BountyFit is evidence-first opportunity triage: inspectable decisions, explicit uncertainty, and no API key or uploaded listing text."

## Capture checklist

- 1920×1080.
- Browser zoom 100%.
- No unrelated tabs, notifications, account info, or personal paths.
- Use only synthetic/sample listing text.
- Keep the uncertain-evidence flow in the middle; it is the main differentiator.
- No copyrighted music.
- Keep total video comfortably under 3 minutes.
